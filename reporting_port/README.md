# Portable ICD-10 repository issue reports

This folder is the minimal standalone port of the per-repository report generator.
It searches OpenSAFELY repositories and writes one Markdown file per affected
repository, split between `repo_emails/ehrql/` and
`repo_emails/cohortextractor/`. X-padding-only reports are written separately
to `repo_emails/ehrql-x-padding/`.

The main ehrQL reports can contain three issue types:

- missing five-character modifiers;
- codes moved between ICD-10 2016 and 2019; and
- codes whose definitions changed between ICD-10 2016 and 2019.

The parallel ehrQL X-padding reports contain only missing-X-padding findings.
A repository can appear in either or both ehrQL directories.

Cohort Extractor reports contain only the latter two. A moved-code finding is
suppressed when Cohort Extractor's prefix matching already covers the old and
new codes.

## Requirements and use

- Python 3.12 (the code uses only the standard library).
- The GitHub CLI, authenticated with access to public OpenSAFELY repositories:
  `gh auth login`.

Run from the parent repository:

```sh
python -m reporting_port.generate_reports
```

The included GitHub search cache avoids repeating searches. To discard it and
refresh every search:

```sh
python -m reporting_port.generate_reports --force
```

GitHub is still queried for `project.yaml`, current file contents, and default
branches. Generated reports omit issue sections with no
findings, and are placed in
`reporting_port/repo_emails/`; existing Markdown files there are replaced.

## Portable data inputs

All inputs are under `data/`:

- `swapped_codes.json`: 2019 codes, descriptions, and their corresponding 2016
  HES APCS codes.
- `changed_code_definitions.json`: codes with clinically different 2016 and
  2019 definitions.
- `project_type_overrides.json`: optional manual `ehrql`, `cohortextractor`, or
  `ignore` classifications, keyed by repository name.
- `code_usage_combined_apcs.csv`: all-diagnosis usage counts. Only
  `icd10_code` and `apcs_all_count` are consumed; rows are summed across years.
- `prefix_matching_repos.csv`: repository/codelist rows containing
  `current_event_count`, `event_count_with_x_padding`, and
  `event_count_with_prefix_matching`.
- `prefix_matching_details.json`: the exact modifier codes and three-character
  codes responsible for those prefix-matching count changes, plus the matching
  2024-25 all-diagnosis event counts.
- `github_code_search_cache.json`: optional derived cache, regenerated by the
  CLI when missing or when `--force` is used.

The upstream codelist extraction, coverage analysis, ONS counts, consolidated
reports, and email-delivery machinery are deliberately not included.
